# 遗物系统实现任务

本文档基于 `docs/遗物机制规则.md` 拆分后续开发任务。任务按依赖顺序排列，先完成伤害与子弹基础事件，再接入遗物运行时系统和现有遗物迁移。

## 1. 实现范围

第一阶段实现：

- 伤害上下文扩展。
- 敌人受伤事件上下文。
- 子弹生命周期事件。
- 子弹命中效果调度。
- 遗物运行时系统。
- `RelicData.EffectKey` 强制绑定。
- 现有 4 个遗物迁移到接口实现。
- 商店过滤不可获得遗物。

第一阶段只保留接口，不接入完整逻辑：

- `IEnemyKilledRelicEffect`
- `IPickupRelicEffect`
- `IFloorStartRelicEffect`

第一阶段不改动：

- 道具 `ItemData` 数值模板系统。
- 道具购买效果逻辑。
- 非遗物来源的复杂状态 DOT 系统。

## 2. 阶段一：伤害上下文改造

目标：让所有敌人伤害都带明确来源、元素和触发控制信息。

预计改动：

- 扩展 `Assets/Game/Scripts/Data/DamageHitInfo.cs`。
- 新增伤害来源类别枚举，例如 `DamageSourceCategory`。
- 新增伤害元素枚举，例如 `DamageElementType`。
- 新增 `EnemyDamagedContext` 数据结构。
- 调整现有创建 `DamageHitInfo` 的调用点。

关键字段：

```text
Amount
IsCritical
SourceCategory
Element
CanTriggerDamageReaction
CanTriggerKillEffects
SourceRelicId
SourceEffectKey
RootTriggerId
Generation
```

验收标准：

- 普通子弹伤害可标记为 `ProjectilePrimary`。
- 遗物二次伤害可标记为 `ProjectileEffect` 或 `RelicReaction`。
- 状态持续伤害未来可通过 `StatusDot` 排除受伤反应。
- 旧的普通伤害构造仍能安全迁移，不出现编译错误。

## 3. 阶段二：敌人受伤事件接入

目标：敌人实际扣血后统一产生 `EnemyDamagedContext`，供受伤反应遗物监听。

预计改动：

- 梳理 `GameCombatController` 和 `GameCombatRuntimeController` 中敌人伤害结算入口。
- 将伤害结算结果包装为 `EnemyDamagedContext`。
- 在结算完成后通知遗物运行时系统。
- 保持现有击杀、掉落、分数和伤害跳字流程不变。

验收标准：

- 子弹本体伤害会产生一次受伤事件。
- 子弹特效伤害会产生独立受伤事件。
- `CanTriggerDamageReaction = false` 的伤害不会触发受伤反应遗物。
- 击杀、金币、经验、得分逻辑保持原行为。

## 4. 阶段三：子弹生命周期事件

目标：让子弹按固定生命周期进入生成、命中、消失和回收阶段。

预计改动：

- 新增子弹消失原因枚举，例如 `ProjectileExpireReason`。
- 调整 `GameProjectileCombatController` 的移除逻辑。
- 区分 `HitConsumed`、`LifeTimeEnded`、`ManualRelease`。
- 子弹生成时记录效果快照。
- 子弹命中时携带命中上下文。
- 子弹消失时携带消失上下文。

消失原因规则：

```text
HitConsumed     触发 OnProjectileExpire
LifeTimeEnded   触发 OnProjectileExpire
ManualRelease   不触发 OnProjectileExpire
```

验收标准：

- 命中且无穿透时触发消失效果。
- 寿命结束时触发消失效果。
- 清场、重开、对象池主动释放不触发消失效果。
- 穿透命中仍触发 `OnProjectileHit`。
- 派生弹生命周期和普通弹一致。

## 5. 阶段四：命中效果调度器

目标：将子弹命中特效从具体战斗流程中抽离，由统一调度器和上下文执行。

预计新增：

- `ProjectileEffectDispatcher`
- `ProjectileHitEffectContext`
- `ProjectileExpireEffectContext`

预计调整：

- `GameProjectileCombatController` 调用调度器执行命中特效。
- 命中特效使用子弹生成时的效果快照。
- 调度顺序按 `ExecutionOrder`、获得顺序、`EffectKey` 排序。

上下文能力：

```text
GetAttackDamage()
FindNearestEnemies()
FindEnemiesInRadius()
ApplyDamage()
SpawnChildProjectile()
HasProjectileTag()
AddProjectileTag()
```

验收标准：

- 命中特效在子弹本体伤害和受伤事件之后执行。
- 多个命中特效按稳定顺序执行。
- 效果类不直接操作敌人列表、对象池和伤害跳字。
- 派生弹继承源子弹效果快照。

## 6. 阶段五：遗物运行时系统

目标：统一管理遗物拥有状态、堆叠、效果实例、接口注册和触发调度。

预计新增：

- `GameRelicRuntimeController`
- `RelicRuntimeEntry`
- `RelicEffectFactory`
- 遗物效果接口文件。

建议接口：

```text
IRelicEffect
IOnAcquireRelicEffect
IPassiveStatRelicEffect
IProjectileHitRelicEffect
IProjectileExpireRelicEffect
IDamageReactionRelicEffect
IEnemyKilledRelicEffect
IPickupRelicEffect
IFloorStartRelicEffect
```

运行时职责：

- 检查 `RelicId`、`EffectKey` 和 `MaxStack`。
- 维护堆叠层数和获得顺序。
- 通过 `EffectKey` 创建效果实例。
- 按接口注册到对应列表。
- 提供子弹效果快照。
- 调度获得、被动、命中、消失和受伤反应效果。
- 对商店提供 `CanAcquireRelic` 查询。

验收标准：

- `EffectKey` 为空或未知时拒绝注册并报错。
- 已达到堆叠上限的遗物无法再次获得。
- 同阶段效果顺序稳定。
- `OnKill`、`OnPickup`、`OnFloorStart` 接口存在但第一阶段不接入完整逻辑。

## 7. 阶段六：RelicData 和资产迁移

目标：让所有遗物资产显式绑定 `EffectKey`，不再依赖旧 `EffectType` 推断。

预计改动：

- 修改 `Assets/Game/Scripts/Data/RelicData.cs`。
- 新增 `effectKey`、`maxStack`，保留或整理 `executionOrder`。
- 更新现有遗物资产。

现有资产迁移：

```text
Relic_OldCharm.asset          effectKey = old_charm
Relic_GoldCompass.asset       effectKey = gold_compass
Relic_CollectorsLedger.asset  effectKey = collectors_ledger
Relic_BurstCore.asset         effectKey = burst_core
```

验收标准：

- 所有现有遗物资产都有非空 `effectKey`。
- 运行时不再使用旧 `EffectType` 推断遗物效果。
- 旧字段如暂时保留，不影响新运行时逻辑。

## 8. 阶段七：现有遗物效果迁移

目标：将现有 4 个遗物迁移为接口效果类，并保持当前行为。

迁移目标：

```text
OldCharmRelicEffect
-> IOnAcquireRelicEffect
-> 获得时最大生命 +10

GoldCompassRelicEffect
-> IPassiveStatRelicEffect 或金币收益聚合接口
-> 金币收益 +25%

CollectorsLedgerRelicEffect
-> IPassiveStatRelicEffect
-> 每拥有 1 件遗物，暴击率 +2%

BurstCoreRelicEffect
-> IProjectileHitRelicEffect
-> IProjectileExpireRelicEffect
-> 命中或消失时造成范围爆炸
```

验收标准：

- 购买旧护符后最大生命提升。
- 购买金币罗盘后后续金币收益提升。
- 收藏者账本按遗物数量提供暴击率。
- 爆裂弹芯在命中和有效消失时触发爆炸。
- 行为与迁移前保持一致或符合新文档规则。

## 9. 阶段八：商店和 UI 接入

目标：商店不再出售不可获得遗物，并让 UI 能显示当前遗物信息。

预计改动：

- `GameShopController` 使用 `GameRelicRuntimeController.CanAcquireRelic` 过滤候选池。
- `GameCombatController` 购买遗物时改为调用遗物运行时系统。
- 暂停或结算文本可继续先显示名称列表，后续再做独立遗物 UI。

验收标准：

- 已拥有且不可堆叠的遗物不再刷新出来。
- `EffectKey` 配置错误的遗物不进入商店池。
- 购买遗物后能立即注册并生效。
- 现有商店购买道具流程不受影响。

## 10. 阶段九：验证与回归

目标：确认基础战斗闭环和迁移遗物行为稳定。

建议验证场景：

- 开始新局，普通子弹可正常命中并造成伤害。
- 穿透子弹多次命中，每次合法命中触发命中特效。
- 子弹寿命结束触发消失效果。
- 清场或重新开始不触发消失效果。
- 购买 4 个现有遗物后行为正常。
- 达到堆叠上限的遗物不再进入商店。
- `EffectKey` 为空或未知时有明确错误日志。

回归关注：

- 击杀统计。
- 经验和金币掉落。
- 分数统计。
- 暴击率计算。
- 子弹穿透和反弹。
- 商店刷新和锁定。

## 11. 推荐开发顺序

推荐按以下顺序实施，每个阶段通过验收后再进入下一阶段：

```text
1. 伤害上下文改造
2. 敌人受伤事件接入
3. 子弹生命周期事件
4. 命中效果调度器
5. 遗物运行时系统
6. RelicData 和资产迁移
7. 现有遗物效果迁移
8. 商店和 UI 接入
9. 验证与回归
```
