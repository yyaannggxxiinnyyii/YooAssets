# 遗物机制规则

本文档记录遗物系统改造讨论中的当前规则，用于后续实现拆分和协作对接。本文先作为遗物、战斗事件、伤害事件和子弹特效触发规则的专项设计文档，后续实现完成后再同步到 `docs/DESIGN.md`。

## 1. 系统边界

- 本轮主要讨论和改造遗物系统；涉及道具与遗物边界冲突时，需要同步清理道具侧旧入口。
- 道具继续走 `ItemData` 模板化数值效果，只承载直接数值变化或简单倍率修正，可配置多条正面或负面效果。
- 遗物走机制型接口实现，不强行做通用 ScriptableObject 效果模板；遗物可以修改属性数值，但不受限于属性数值。
- `RelicData` 继续保留，负责展示、商店引用、唯一 ID、堆叠规则和效果绑定键。
- 道具不得直接监听战斗事件、投射物生命周期、敌人受伤事件，也不得生成派生投射物或触发连锁机制。

## 2. 遗物定位

遗物主要负责特殊机制，例如：

- 子弹命中特效。
- 子弹消失特效。
- 敌人受伤反应。
- 击杀触发。
- 拾取触发。
- 楼层开始触发。
- 获得时立即触发。
- 被动属性聚合。

道具和遗物按以下规则划分：

- 道具负责直接、可立即应用的数值或简单属性修正，例如攻击力 +5、最大生命 +2、暴击率提升、攻击间隔缩短、攻击力 +40% 且移动速度 -10%。
- `ProjectileScale` 可以保留在道具侧，因为它只是投射物尺寸的简单数值缩放，不引入新的触发链路。
- 遗物负责事件驱动或机制型效果，例如命中后追加伤害、消失时触发效果、受伤反应、击杀触发、拾取触发、派生弹生成、范围伤害和连锁反应；遗物也可以在条件满足时修改属性数值。
- 道具不能包含条件判断或规则触发，例如“血量 <= 2 时获得暴击率和移速”属于遗物。
- `ProjectileSplitOnDisappear` 归属遗物，因为它依赖投射物消失生命周期并生成派生投射物，不属于普通数值道具。
- 当一个效果需要 `IProjectileHitRelicEffect`、`IProjectileExpireRelicEffect`、`IDamageReactionRelicEffect` 等机制接口时，默认应实现为遗物，而不是扩展 `ItemData.ItemEffectType`。

遗物不优先承担普通数值道具职责，例如单纯攻击力 +5、最大生命 +2 这类效果仍由道具处理；但带条件、触发时机、生命周期或规则判断的属性变化应实现为遗物。

## 3. 堆叠规则

- 遗物默认全局唯一，`RelicData.GlobalUnique` 默认为 `true`。
- 使用 `RelicId` 判断唯一性。
- 如果某个遗物允许重复，需要关闭 `GlobalUnique`，并在 `RelicData` 中配置堆叠上限，例如 `MaxStack`。
- 不同遗物之间的效果默认可以叠加。
- 同一遗物多层堆叠时，由具体遗物效果实现决定如何处理层数。
- 商店会过滤已经拥有的全局唯一遗物，以及已经达到堆叠上限的非唯一遗物。

## 4. 遗物数据规则

`RelicData` 必须包含以下运行时字段：

```text
RelicId
DisplayName
Description
Icon
EffectKey
GlobalUnique
MaxStack
ExecutionOrder
```

字段规则：

- `RelicId` 必填，用于唯一性和堆叠计数。
- `EffectKey` 必填，是遗物效果绑定的唯一运行时入口。
- `EffectKey` 为空时直接报错并拒绝注册遗物。
- `EffectKey` 未被工厂支持时直接报错并拒绝注册遗物。
- 不再根据旧的 `EffectType` 或 `TriggerType` 推断遗物效果。
- `GlobalUnique` 默认为 `true`，表示获得一次后不能再次获得，也不再进入商店候选池。
- `MaxStack <= 0` 时按 1 处理，并输出配置警告。
- `GlobalUnique` 为 `false` 时才允许按 `MaxStack` 重复获得。
- `ExecutionOrder` 用于同阶段效果排序。

旧字段如果暂时保留，仅用于资产过渡或编辑器查看，运行时不依赖它们。

## 5. 遗物效果实现规则

遗物效果通过接口实现，而不是模板解释器。每个具体遗物可以实现一个或多个触发接口。

建议接口方向：

```text
IRelicEffect
IOnAcquireRelicEffect
IPassiveStatRelicEffect
IProjectileHitRelicEffect
IProjectileExpireRelicEffect
IDamageReactionRelicEffect
IEnemyKilledRelicEffect
IPickupRelicEffect
IFloorStartRelicEffect
```

示例归属：

```text
霹雳糖：IProjectileHitRelicEffect
闪电核心：IDamageReactionRelicEffect
分裂子弹：IProjectileHitRelicEffect
旧护符：IOnAcquireRelicEffect
金币罗盘：IPassiveStatRelicEffect 或奖励倍率聚合接口
```

## 6. 运行时注册规则

遗物运行时系统暂定为 `GameRelicRuntimeController`，负责拥有状态、效果实例注册、触发调度和商店过滤查询。

获得遗物时执行以下流程：

1. `relicData == null` 时失败并输出日志。
2. `RelicId` 为空时失败并输出错误。
3. `EffectKey` 为空时失败并输出错误。
4. `EffectKey` 未被工厂支持时失败并输出错误。
5. 读取 `MaxStack`，小于等于 0 时按 1 处理并输出警告。
6. `GlobalUnique` 为 `true` 且已经拥有同 `RelicId` 时失败，不重复获得。
7. `GlobalUnique` 为 `false` 且当前 `StackCount >= MaxStack` 时失败，不重复获得。
8. 根据 `EffectKey` 创建或获取对应遗物效果实例。
9. 写入拥有遗物列表、堆叠层数和获得顺序。
10. 按接口类型注册到不同运行时列表。
11. 按 `ExecutionOrder`、获得顺序和 `EffectKey` 排序。
12. 触发 `OnAcquire`。
13. 刷新被动属性聚合。

运行时可维护以下效果列表：

```text
_onAcquireEffects
_passiveStatEffects
_projectileHitEffects
_projectileExpireEffects
_damageReactionEffects
_enemyKilledEffects
_pickupEffects
_floorStartEffects
```

商店过滤规则：

- `CanAcquireRelic(relicData) == false` 的遗物不进入商店候选池。
- 已拥有的全局唯一遗物不进入商店候选池。
- 已达到堆叠上限的非唯一遗物不进入商店候选池。
- `RelicId` 为空、`EffectKey` 为空或 `EffectKey` 未知的遗物不进入商店候选池，并输出配置错误。

`EffectKey` 第一版通过显式工厂映射到具体 C# 效果类，不使用反射。

示例：

```text
old_charm -> OldCharmRelicEffect
gold_compass -> GoldCompassRelicEffect
collectors_ledger -> CollectorsLedgerRelicEffect
burst_core -> BurstCoreRelicEffect
```

## 7. 子弹效果规则

子弹特效属于遗物效果的一种触发结果，但不使用统一 ScriptableObject 模板。

- 子弹本体命中先结算基础伤害。
- 基础伤害结算完成后，广播受伤事件。
- 再执行 `IProjectileHitRelicEffect`。
- 子弹消失时执行 `IProjectileExpireRelicEffect`。
- 子弹特效造成的伤害必须明确伤害类别和是否可触发受伤反应。
- 派生弹继承源子弹的效果快照。
- 每个效果自己决定是否允许在派生弹上执行。
- 分裂、连锁等高风险效果需要在具体逻辑里控制代数和次数。
- 所有可能生成派生弹或连锁伤害的效果必须有防递归限制。

## 8. 命中效果系统规划

命中特效系统负责统一调度子弹命中后触发的机制效果。遗物是效果来源之一，但命中特效不直接散落在子弹命中代码里。

### 8.1 调度入口

子弹命中特效由统一调度器执行，暂定为：

```text
ProjectileEffectDispatcher
```

一次合法命中后的顺序：

```text
1. 子弹本体伤害结算
2. 广播 EnemyDamagedContext
3. 调度 OnProjectileHit 效果
4. 处理穿透、伤害衰减和消失
```

命中特效永远在子弹本体伤害和受伤事件之后执行。

### 8.2 命中特效接口

第一版接口方向：

```csharp
public interface IProjectileHitRelicEffect : IRelicEffect
{
    void OnProjectileHit(ProjectileHitEffectContext context);
}
```

第一版不做返回值，不允许某个效果取消后续效果。后续如果需要“命中后吞掉子弹”或“阻止后续效果”，再增加返回结果。

### 8.3 同阶段执行顺序

同阶段多个效果按稳定顺序执行：

```text
ExecutionOrder 小的先执行
ExecutionOrder 相同，按获得遗物的顺序执行
获得顺序也相同，按 EffectKey 字符串稳定排序
```

建议顺序段：

```text
100-199：命中附加状态类
200-299：命中二次伤害类，例如爆炸、闪电
300-399：派生弹生成类，例如分裂子弹
400-499：特殊收尾类
```

示例：

```text
霹雳糖 ExecutionOrder = 200
分裂子弹 ExecutionOrder = 300
```

这样同一次命中会先触发霹雳糖闪电，再生成分裂弹。

### 8.4 调度快照

- 子弹生成时记录本颗子弹携带的效果快照。
- 子弹命中时调度本颗子弹自己的效果快照。
- 已经在飞行的旧子弹不受之后获得的新遗物影响。
- 调度时使用快照，避免某个效果执行过程中新增或移除遗物导致当前循环变化。

### 8.5 上下文能力

爆炸、闪电、分裂等效果不直接读取控制器内部字段，而是通过 `ProjectileHitEffectContext` 调用统一能力。

建议上下文提供：

```text
Projectile
HitEnemy
HitPosition
PrimaryDamageInfo
ProjectileGeneration
RootTriggerId
GetAttackDamage()
FindNearestEnemies()
FindEnemiesInRadius()
ApplyDamage()
SpawnChildProjectile()
HasProjectileTag()
AddProjectileTag()
```

效果类只写机制逻辑，不直接操作敌人列表、对象池、伤害数字或子弹列表。

### 8.6 示例效果行为

霹雳糖：

```text
OnProjectileHit
-> FindNearestEnemies(HitPosition, 3)
-> ApplyDamage(target, ProjectileEffect + Lightning + CanTriggerDamageReaction)
```

爆炸：

```text
OnProjectileHit 或 OnProjectileExpire
-> FindEnemiesInRadius(center, radius)
-> ApplyDamage(target, ProjectileEffect + Fire 或 Normal)
```

分裂子弹：

```text
OnProjectileHit
-> 检查 ProjectileGeneration 是否超过限制
-> 生成两个随机方向
-> SpawnChildProjectile()
```

### 8.7 派生弹效果快照

- 派生弹生命周期和普通弹完全一致。
- 派生弹效果快照来自源子弹快照，而不是重新读取当前玩家遗物。
- 每个效果自己决定是否允许在派生弹上执行。
- 分裂类效果默认限制代数，避免无限分裂。
- 普通命中二次伤害类效果，例如霹雳糖，可以允许派生弹继续触发。

示例：

```text
分裂弹命中敌人
-> 可以触发霹雳糖
-> 默认不再触发分裂子弹，除非分裂子弹显式允许更高代数
```

### 8.8 第一版限制

第一版先不支持：

```text
取消命中
取消后续效果
修改本体伤害
命中特效之间互相插队
反弹触发效果
每帧飞行效果
```

第一版优先把 `OnProjectileHit` 的二次伤害和派生弹生成打稳。

## 9. 子弹生命周期事件规划

单颗子弹从生成到回收按固定生命周期执行。第一版只开放少量稳定触发点给遗物，其他阶段作为子弹和战斗系统内部流程。

### 9.1 标准流程

```text
OnProjectileSpawn
ProjectileTick
ProjectileHitCheck
OnProjectileHitStart
ProjectilePrimaryDamage
OnEnemyDamaged
OnProjectileHit
ProjectilePostHit
OnProjectileExpire
OnProjectileReleased
```

流程说明：

- `OnProjectileSpawn`：子弹生成并初始化，可用于注册本颗子弹携带的效果快照。
- `ProjectileTick`：子弹飞行中更新，第一版不开放给遗物。
- `ProjectileHitCheck`：检测是否命中敌人，属于内部阶段。
- `OnProjectileHitStart`：命中确认并记录目标，第一版暂不开放给遗物。
- `ProjectilePrimaryDamage`：子弹本体伤害结算。
- `OnEnemyDamaged`：敌人扣血后广播受伤事件。
- `OnProjectileHit`：子弹合法命中后执行命中特效。
- `ProjectilePostHit`：处理穿透、伤害衰减和销毁判定。
- `OnProjectileExpire`：子弹进入消失阶段。
- `OnProjectileReleased`：清理并回收到对象池，不开放给遗物。

### 9.2 第一版开放触发点

第一版开放给遗物的子弹触发点：

```text
OnProjectileSpawn
OnProjectileHit
OnProjectileExpire
```

其他子弹阶段先作为内部流程，避免触发点过多导致行为难以控制。

### 9.3 已确认规则

- 命中导致的销毁会触发 `OnProjectileExpire`。
- 穿透命中后会触发 `OnProjectileHit`。
- 每次合法命中默认都可以触发 `OnProjectileHit`。
- 同一颗子弹是否限制某个效果每颗子弹只触发一次，由具体遗物效果自行控制。
- 派生弹生命周期和普通弹完全一致。
- 派生弹和普通弹的区别只体现在生成上下文，例如触发代数、父子关系和继承效果列表。

### 9.4 待确认规则

- 反弹暂作为子弹内部运动逻辑，不开放遗物触发；如果后续需要“反弹时触发效果”，再增加 `OnProjectileBounce`。

### 9.5 子弹消失原因

`OnProjectileExpire` 需要携带消失原因，第一版先定义三种：

```text
HitConsumed     命中后无穿透次数，被消耗
LifeTimeEnded   飞行时间结束
ManualRelease   系统主动清理
```

触发规则：

- `HitConsumed`：触发 `OnProjectileExpire`。
- `LifeTimeEnded`：触发 `OnProjectileExpire`。
- `ManualRelease`：不触发 `OnProjectileExpire`。

如果某个遗物只响应特定消失原因，由具体遗物效果在 `OnProjectileExpire(context)` 中自行判断。

## 10. 伤害上下文规则

后续伤害不应只传 `int damage`，需要带上下文。

建议包含：

```text
DamageCategory
DamageElement
CanTriggerDamageReaction
SourceRelicId
SourceEffectKey
RootTriggerId
Generation
IsStatusDot
```

推荐伤害类别：

```text
ProjectilePrimary      子弹本体伤害
ProjectileEffect       子弹特效伤害
RelicReaction          受伤反应伤害
WeaponSkill            武器技能伤害
StatusDot              状态持续伤害
Environment            环境伤害
```

推荐元素类型：

```text
Normal
Fire
Lightning
Poison
Ice
```

## 11. 伤害结算事件规划

一次伤害需要拆成两层数据：伤害信息和受伤事件上下文。

### 11.1 伤害信息

`DamageHitInfo` 只描述“这次伤害是什么”，不包含目标、位置等运行时命中信息。

建议字段：

```text
Amount
IsCritical
SourceCategory
Element
CanTriggerDamageReaction
CanTriggerKillEffects
SourceRelicId
SourceEffectKey
RootTriggerId
Generation
```

字段用途：

- 区分子弹本体伤害、子弹特效伤害、遗物反应伤害等来源类别。
- 区分普通、火、雷、毒、冰等元素。
- 控制本次伤害是否允许触发受伤反应。
- 控制本次伤害是否允许触发击杀类效果。
- 使用 `RootTriggerId` 和 `Generation` 限制递归和连锁深度。
- 使用 `SourceRelicId` 和 `SourceEffectKey` 记录具体来源，便于过滤自身递归和调试。

第一版暂不加入以下字段，等需求明确后再扩展：

```text
ArmorPierce
Knockback
StatusChance
AreaRadius
ChainCount
```

### 11.2 受伤事件上下文

`EnemyDamagedContext` 描述“这次伤害发生在哪里、打到了谁、结算结果是什么”。

建议字段：

```text
TargetEnemy
HitPosition
DamageInfo
ActualDamage
Killed
SourceProjectile
```

字段用途：

- `TargetEnemy` 表示实际受伤目标。
- `HitPosition` 表示伤害发生位置，供闪电、爆炸、击退、特效等逻辑使用。
- `DamageInfo` 保留原始伤害信息。
- `ActualDamage` 表示经过生命、护盾或后续防御计算后的实际伤害。
- `Killed` 表示本次伤害是否击杀目标。
- `SourceProjectile` 可选记录来源子弹，供命中链、派生弹和调试使用。

### 11.3 第一版规则

- 所有敌人受伤结算完成后，统一广播 `EnemyDamagedContext`。
- `IDamageReactionRelicEffect` 只监听 `EnemyDamagedContext`，不直接依赖子弹命中逻辑。
- 状态持续伤害应通过 `SourceCategory = StatusDot` 或等价字段排除受伤反应。
- 遗物反应伤害默认设置 `CanTriggerDamageReaction = false`，避免自身递归。
- 子弹特效伤害是否能触发受伤反应，由具体效果显式设置。

## 12. 受伤反应规则

`IDamageReactionRelicEffect` 监听统一的敌人受伤事件。

默认规则：

- 可响应子弹本体伤害。
- 可响应允许触发受伤反应的子弹特效伤害。
- 可响应允许触发受伤反应的武器技能伤害。
- 不响应状态持续伤害，例如点燃、中毒。
- 不响应自身或其他受伤反应造成的 `RelicReaction` 伤害，除非以后显式开放。
- 每个反应效果应通过 `RootTriggerId` 或 `Generation` 防止递归。

## 13. 示例遗物规则

### 霹雳糖

```text
触发：子弹命中后
效果：对命中点附近最近 3 个敌人造成闪电伤害
伤害类别：ProjectileEffect
元素：Lightning
CanTriggerDamageReaction：true
```

### 闪电核心

```text
触发：敌人受到有效伤害后
响应：ProjectilePrimary、ProjectileEffect、WeaponSkill
排除：StatusDot、RelicReaction
效果：触发一次闪电攻击
伤害类别：RelicReaction
元素：Lightning
CanTriggerDamageReaction：false
```

### 分裂子弹

```text
触发：子弹命中后
效果：随机两个方向生成派生弹
继承：继承基础弹体属性
限制：默认不继承分裂能力，或最多继承 1 代
```

## 14. 待继续讨论的问题

- 击杀、拾取、楼层开始等非子弹触发点是否第一阶段实现。
