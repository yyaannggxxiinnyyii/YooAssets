# 关卡房间与难度系统设计

本文档记录关卡流程、房间选择、敌人生成、Boss 层、场景式商店、评分与数据结构方案。后续实现以本文档为准，现有 `FloorData` 先保留兼容，逐步迁移到 `StageData` 驱动。

## 设计目标

- 将当前“层数堆叠”改造成完整关卡流程。
- 每关固定若干房间节点，Boss 节点由 `BossData.CombatNode` 配置决定，通关条件为完成全部房间节点。
- 战斗结束后不弹完整结算 UI，而是在场景中生成门、宝箱、奖励 NPC、商店物件等可交互对象。
- 普通战斗房使用固定预算生成有限敌人，支持提前清场和评分追求。
- Boss 层不使用固定支援怪刷新器，Boss 召唤物由 Boss 技能控制。
- 商店改为场景式商店，商品实体摆放在场景中，玩家靠近显示 Tooltip 并交互购买。
- 评分只记录分数，不做评级，不根据评级发奖励；后续排行榜直接使用总分。

## 术语

| 术语 | 含义 |
|---|---|
| Stage / 关卡 | 一整关，例如第一关、第二关。 |
| Combat Node / 房间节点 | 推进 B1/B30 的关卡节点。普通房、精英房、Boss 房、商店房、事件房和宝箱房都占用节点。 |
| Room / 房间 | 玩家实际进入的房间，可以是战斗房，也可以是商店、事件、宝箱等中转房。 |
| Transit Room / 中转房 | 非战斗房间，例如商店房、事件房、宝箱房。中转房也占用房间节点，离开后进入其绑定的后续战斗房。 |
| Room Option / 门选项 | 战斗结束后生成的可交互入口，玩家选择后进入对应房间。 |
| Spawn Budget / 生成预算 | 普通层用于生成敌人的总成本预算。 |

## 总体流程

一关包含 30 个房间节点：

```text
B1 - B14   普通/精英/商店/事件/宝箱房间节点
B15        可配置 Boss
B16 - B29  普通/精英/商店/事件/宝箱房间节点
B30        可配置 Boss 或普通终点房间
```

战斗节点结束后，进入场景内收尾状态：

```text
停止刷怪
清理剩余敌人
结算本层分数和收益
生成门、宝箱、奖励 NPC 等场景交互物
如果有升级词条选择，弹出升级 UI
如果有武器强化选择，弹出武器强化 UI
恢复玩家控制
玩家交互奖励物或选择门
进入下一房间
```

升级词条和武器强化仍使用 UI 选择界面。商店、宝箱、奖励 NPC、门和事件尽量场景化。

## 房间类型

| 房间类型 | 是否占用房间节点 | 用途 |
|---|---:|---|
| 普通战斗房 | 是 | 标准战斗层。 |
| 精英战斗房 | 是 | 更高难度，完成后给额外奖励。 |
| Boss 房 | 是 | 第 15 / 30 战斗节点固定 Boss。 |
| 商店房 | 是 | 场景式购买道具和遗物。 |
| 事件房 / 协议房 | 是 | 接受挑战或触发特殊事件，第一版可暂缓。 |
| 宝箱房 | 是 | 奖励房，第一版可暂缓为场景宝箱。 |

商店房、事件房、宝箱房也占 B1/B30 进度。进入这些中转房时，需要记录“离开后进入的目标战斗房类型”。

示例：

```text
B14 结束后生成：商店房 / Boss 房
玩家选择商店房
进入商店房，推进为 B15/B30
由于 B15 是固定 Boss 节点，Boss 优先覆盖商店房，实际进入 Boss 房

B13 结束后生成：商店房 / 精英房
玩家选择商店房
进入商店房，推进为 B14/B30
离开商店后进入该商店门绑定的普通或精英战斗房，不再额外推进层数
```

## 门与场景交互

战斗结束后，场景中生成 1-2 个门选项。门不一定是传统门，也可以是传送门、洞口、路牌、商店招牌、Boss 入口等。

推荐表现：

| 类型 | 外观方向 | 颜色方向 |
|---|---|---|
| 普通房 | 普通木门、洞口 | 木色、灰色 |
| 精英房 | 尖刺、危险标识、红色门框 | 红色 |
| 商店房 | 金币、商店牌、老虎机、摊位入口 | 金色 |
| 事件房 | 协议牌、问号、卷轴 | 紫色、青色 |
| 宝箱房 | 宝箱、金色门 | 金色 |
| Boss 房 | 巨大门、警告牌、皇冠/骷髅符号 | 深红、黑色 |

玩家靠近门时显示 Tooltip：

```text
E 进入商店
出售道具和遗物，可使用有限次数刷新商品。
```

```text
E 进入精英房
敌人更强，完成后获得额外奖励。
```

交互规则：

```text
玩家选择某个门
其他门消失
清理当前房间奖励物
进入目标房间
```

## 房间节点生成规则

第一版使用“阶段门池 + 特殊节点覆盖”的方式，不手写 30 层。

普通情况下，每个战斗节点结束后生成两个门。特殊节点可以只生成一个门或固定门组合。

推荐阶段门池：

```text
B1 - B4:
  普通房 / 精英房
  普通房 / 普通房

B5 - B9:
  普通房 / 精英房
  普通房 / 事件房
  商店房 / 精英房

B10 - B14:
  商店房 / 精英房
  商店房 / 普通房
  事件房 / 普通房

B16 - B19:
  普通房 / 精英房
  普通房 / 事件房

B20 - B24:
  商店房 / 精英房
  事件房 / 精英房
  普通房 / 精英房

B25 - B29:
  商店房 / 精英房
  商店房 / 事件房
  商店房 / 普通房
```

Boss 节点强制规则：

```text
如果下一房间节点配置了 BossData，则上一房间结束时只生成 1 个 Boss 门。
Boss 门不需要在 RoomOptionRule 中手动配置。
例如当前 B14 完成，B15 有 BossData，则只显示 Boss 门。
当前 B30 完成且 Stage 总房间数为 30，则直接通关结算，不生成门。
```

第一版实际落地可以先只做：

```text
普通房
精英房
商店房
Boss 房
```

事件房、宝箱房、协议任务先在数据结构中预留。

## 普通层敌人生成

普通战斗房和精英战斗房使用固定预算、有限敌人的生成机制。

核心规则：

```text
本层总预算固定
进入房间时生成完整刷怪计划
敌人分批生成
玩家清怪快时可以提前生成下一批
所有计划敌人最晚在本层结束前 5 秒尽量刷出
时间到即使没有清完，也进入下一流程
提前清完全部计划敌人，可以提前结束本层
```

普通层参数：

```text
层时长：40 秒
刷怪截止：35 秒
批次数：5
默认批次时间：0 / 8 / 16 / 24 / 32 秒
批次预算比例：15% / 20% / 20% / 20% / 25%
提前刷怪阈值：场上敌人 <= 3
提前刷怪最小间隔：2 秒
场上敌人软上限：35
场上敌人硬上限：50
```

预算公式：

```text
本层预算 = 12 + (战斗层数 - 1) * 4
```

第一版暂不加入阶段倍率。试玩后如后半段偏弱，再考虑：

```text
B16 后预算 x1.10
B26 后预算 x1.20
```

时间到处理：

```text
清理剩余敌人
未击杀敌人不给分、经验、金币
进入层结束流程
```

提前清场处理：

```text
所有计划敌人已刷出且全部死亡
提前结束本层
结算清场奖励和速度奖励
```

## 敌人池分段

当前第一版已有四种敌人：

| 敌人类型 | 职责 | 成本 | 建议分数 |
|---|---|---:|---:|
| 近战 A | 基础小怪，数量压力，送基础收益 | 1 | 10 |
| 近战 B | 快速追击，打乱走位，逼迫翻滚 | 2 | 25 |
| 远程怪 | 制造弹幕压力，限制绕圈风筝 | 3 | 40 |
| 坦克怪 | 高血量阻挡，测试单体输出 | 5 | 70 |

敌人池分段：

```text
B1 - B4:
  近战 A 100

B6 - B9:
  近战 A 75
  近战 B 25

B11 - B14:
  近战 A 60
  近战 B 25
  远程怪 15

B16 - B19:
  近战 A 50
  近战 B 25
  远程怪 15
  坦克怪 10

B21 - B24:
  近战 A 40
  近战 B 25
  远程怪 20
  坦克怪 15

B26 - B29:
  近战 A 30
  近战 B 25
  远程怪 25
  坦克怪 20
```

精英房可以复用当前战斗层对应的敌人池，但增加预算和属性倍率。

## 敌人属性成长

普通层基础倍率：

```text
生命倍率 = 1 + (战斗层数 - 1) * 0.08
速度倍率 = 1 + (战斗层数 - 1) * 0.01
伤害倍率 = 1 + (战斗层数 - 1) * 0.03
金币倍率 = 1 + (战斗层数 - 1) * 0.02
经验倍率 = 1 + (战斗层数 - 1) * 0.03
```

速度成长保持保守，避免后期玩家体验变差。数量压力主要由预算和敌人池变化承担。

精英房建议额外倍率：

```text
预算倍率：1.25
生命倍率：额外 x1.15
伤害倍率：额外 x1.10
奖励倍率：1.5
```

精英房完成后生成奖励宝箱。第一版奖励可以先给金币或经验，后续扩展为道具/遗物选择。

## Boss 层

Boss 层规则：

```text
Boss 层无时间限制
Boss 死亡即本层完成
玩家死亡即本关失败
Boss 死亡后清理所有召唤物
第 15 战斗节点为中 Boss
第 30 战斗节点为最终 Boss
```

Boss 层不使用普通层刷怪计划，也不使用独立支援怪刷新器。

Boss 召唤物全部由 Boss 技能控制：

```text
开局触发技能
血量百分比触发技能
冷却触发技能
```

示例：

```text
蜘蛛女王
100% 血：召唤 4 只小蜘蛛
80% 血：召唤 6 只小蜘蛛
50% 血：召唤 2 只精英蜘蛛 + 6 只小蜘蛛

主动技能：
召唤小蜘蛛
冷却 12 秒
召唤 3 只小蜘蛛
```

Boss 技能第一版优先支持：

```text
OnStart
OnHealthPercent
OnCooldown
SummonEnemies
```

后续再扩展：

```text
ProjectileBurst
AreaAttack
Charge
LaserSweep
Shield
Teleport
```

Boss 召唤物收益：

```text
被玩家击杀：正常给分、经验、金币
Boss 死亡后清理：不给分、经验、金币
```

Boss 本体奖励建议直接结算给玩家，不生成需要拾取的掉落：

```text
中 Boss：固定分数 500，经验 20，金币 10
最终 Boss：固定分数 1000，经验 50，金币 25
```

## Boss 挑战与用时

Boss 层不做速度分，但记录 Boss 击杀用时。

记录字段：

```text
Boss 战开始时间
Boss 击杀用时
Boss 战受伤次数
Boss 是否无伤
Boss 召唤物击杀数
Boss 特殊挑战是否完成
```

Boss 击杀用时用于特殊事件或挑战条件，例如：

```text
Boss 前接受特殊任务：2 分钟内击败 Boss
完成后 Boss 死亡时生成奖励宝箱
失败则不生成宝箱
```

第一版可以先只记录用时和受伤次数，挑战系统后续接入。

## 评分机制

评分只记录分数，不做评级，不根据评级发奖励。后续排行榜直接使用总分。

普通层分数来源：

```text
击杀分
清场奖励
速度奖励
无伤奖励
```

击杀分来自敌人 `scoreValue`。

清场奖励：

```text
清场奖励 = 本层击杀分 * 20%
```

只有提前清完全部计划敌人才获得。

速度奖励：

```text
速度奖励 = 本层击杀分 * 剩余时间比例 * 30%
最高不超过本层击杀分的 30%
```

无伤奖励：

```text
0 次受伤：本层击杀分 * 20%
1 次受伤：本层击杀分 * 10%
2 次及以上：0
```

Boss 层分数来源：

```text
Boss 本体击杀分
Boss 召唤物击杀分
Boss 无伤奖励
```

Boss 层不做：

```text
清场奖励
速度奖励
固定支援怪分
评级
```

Boss 无伤奖励：

```text
中 Boss：Boss 本体击杀分 * 20%
最终 Boss：Boss 本体击杀分 * 25%
```

通关结算显示：

```text
总分
击杀分
清场奖励
速度奖励
无伤奖励
Boss 分
总击杀数
清场层数
受伤次数
Boss 用时
游玩时长
```

## 场景式商店

商店房不再使用纯 UI 商店面板，而是场景式商店。

进入商店房后生成：

```text
商店房背景 / 摊位
商人或商店主体
道具商品实例
遗物商品实例
刷新装置
离开门
```

商品摆放：

```text
道具位：3 个
遗物位：3 个
刷新装置：1 个
离开门：1 个
```

玩家靠近商品显示 Tooltip：

```text
[稀有] 曼巴鞋
翻滚次数 +1

价格：16 金币
按 E 购买
```

买不起时显示：

```text
金币不足
```

购买后：

```text
扣除金币
应用道具或遗物
商品消失或显示已售出
```

商店刷新：

```text
刷新装置消耗商店刷新次数
刷新次数来自角色基础配置和遗物/角色被动加成
金币不再用于刷新商店
```

玩家靠近刷新装置显示：

```text
刷新商品
剩余次数：1
按 E 刷新
```

商品锁定第一版可以暂缓。现有锁定逻辑保留，场景式锁定交互后续再做。

商店房离开门：

```text
玩家购买/刷新完成后交互离开门
进入商店绑定的目标战斗房
```

## 无伤奖励与特殊奖励

层结束后不弹完整结算 UI。奖励通过场景交互物表达。

普通层无伤时可以生成奖励 NPC：

```text
小动物 NPC：这是你的无伤奖励！
奖励：金币 / 经验 / 小治疗 / 临时护盾
```

Boss 特殊挑战完成时生成宝箱：

```text
Boss 击杀后生成挑战宝箱
玩家交互宝箱获得奖励
```

第一版可先实现：

```text
完成才生成宝箱或奖励 NPC
失败不生成
```

### 商店配置归属

场景式商店不再作为 `StageData` 的子配置维护，避免同一批商品数据、价格和摆放点出现两个配置入口。

职责划分：

```text
StageData / StageRoomOptionData：
StageData 通过门规则决定是否出现商店门；StageRoomOptionData 配置门显示内容、门外观 ID、商店离开后进入哪类战斗房。

GameShopController：
继续配置 ShopItemData 商品池、道具/遗物数量、品质权重、默认价格和刷新规则。

商店房 Prefab：
通过 GameStageRoomView 标记房间边界、玩家出生点和 DoorRoot。
通过 StageShopOfferLayoutController 或 StageShopOfferPoint 配置场景商品槽位和摆放。
```

### StageRunState

运行时状态。

建议字段：

```text
当前 StageID
当前战斗层数
当前房间类型
当前分数
总击杀数
当前层击杀数
当前层受伤次数
当前层是否清场
当前门选项
中转房离开后的目标战斗房类型
Boss 开始时间
Boss 击杀用时
Boss 战受伤次数
已选择路线记录
```

## 与现有系统的关系

现有 `FloorData` 暂不删除。

迁移策略：

```text
第一步：新增 StageData 和房间流程系统。
第二步：让 StageData 成为主流程配置。
第三步：FloorData 退化为单层覆盖配置，或保留作为旧流程兼容。
第四步：逐步将敌人刷新和 Boss 从当前控制器迁移到 StageData 驱动；商店内容继续由 GameShopController 驱动，StageData 只负责商店房入口流程。
```

现有升级词条和武器强化 UI 继续沿用：

```text
战斗结束后如果有升级次数，弹升级选择 UI。
如果有武器强化次数，弹武器强化 UI。
选择完成后恢复玩家控制，再让玩家交互门和奖励物。
```

现有商店数据继续沿用：

```text
ShopItemData 仍作为商品数据。
GameShopController 的道具/遗物分池、权重、固定价格、刷新次数规则继续使用。
后续只将表现层从 UI 面板改为场景商品实例。
```

## 第一版实现范围

建议第一版只做以下内容：

```text
StageData 基础配置
RoomType / RoomOptionRule / RoomOptionData
普通房、精英房、商店房、Boss 房
战斗结束后生成门
玩家交互门进入目标房间
普通层固定预算刷怪计划
场景式商店基础购买和刷新
Boss 层无时间限制
Boss 召唤物由技能控制的基础框架
分数记录
通关后显示总分
```

```text
复杂 Boss 攻击技能
场景式商品锁定
商人对话
复杂宝箱奖励池
评分评级
```
